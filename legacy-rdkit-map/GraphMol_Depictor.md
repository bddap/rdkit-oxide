# GraphMol – Depictor Sub-module Map

Location: `rdkit/Code/GraphMol/Depictor`

The **Depictor** converts 3-D (or SMILES-only) molecules into aesthetically
pleasing 2-D coordinate layouts suitable for cheminformatics drawing and
fingerprint generation.  It offers two back-ends:

* RDKit’s original distance-geometry and force-field layout algorithm.
* The external *CoordGen* library (Schrödinger) when compiled in; controlled by
  global `RDDepict::preferCoordGen` flag.

-------------------------------------------------------------------------------

## 1. Public API (`RDDepictor.h`)

| Function | Description |
|----------|-------------|
| `compute2DCoords(ROMol&, const Compute2DCoordParameters&)` | Core entry - generates coordinates, adds conformer, returns `confId`. |
| `compute2DCoords(ROMol&, const INT_POINT2D_MAP* coordMap, …)` | Legacy overload with ad-hoc parameters. |
| `setRingSystemTemplates(path)` / `addRingSystemTemplates()` / `loadDefaultRingSystemTemplates()` | Supply template library (CXSMILES lines) to improve common ring drawings. |

`Compute2DCoordParameters` packs ~10 knobs: `coordMap`, `canonOrient`, `nSamples`, `permuteDeg4Nodes`, `useRingTemplates`, etc.

-------------------------------------------------------------------------------

## 2. Implementation files

| File | Purpose |
|------|---------|
| `RDDepictor.cpp` | Dispatcher: chooses CoordGen vs internal, handles ring-template embedding, canonical orientation, coordinate map constraints, and sampling.* |
| `DepictUtils.{h,cpp}` | Helper geometry routines: triangle/bond length heuristics, random rotatable bond flips, canonical alignment using principal axes, `setDCoords()` editing of conformers. |
| `EmbeddedFrag.{h,cpp}` | Represents a fragment with pre-embedded coordinates (e.g., rings, user templates); functions `embedRing()`, `mergeFragments()`. |
| `Templates.{h,cpp}` | Loads template CXSMILES database at start-up, organises by hash of *skeleton SMILES* for quick lookup. |
| `TemplateSmiles.h` | Large string array holding built-in default templates embedded at compile time (generated by script). |
| `Basement/` | Legacy examples not built by default. |

*Internal algorithm (RDKit path)*
1. If `useRingTemplates`, attempt to match ring systems to template DB via
   substructure search; if found, coordinates are placed directly.
2. For remaining scaffold run 2-D distance geometry using a weighted
   distance-matrix based on topological distances and idealised bond lengths.
3. Perform random sampling (`nFlipsPerSample`) of rotatable bonds, pick
   depiction minimising an edge-crossing and overlap cost function.
4. Align long principal axis horizontally if `canonOrient`.

-------------------------------------------------------------------------------

## 3. Testing

* C++: `catch_tests.cpp`, `testDepictor.cpp` – ring template placement, coordMap constraints, reproducing crystallographic distances.
* Python side (outside this repo) uses `Chem.Draw` tests.

Aux data under `test_data/` (CSV of expected RMSD between 2-D distances and target matrices).

-------------------------------------------------------------------------------

## 4. Dependencies

• `GraphMol/Substruct` for ring template matching.  
• `Geometry` for 2-D vectors, eigen decomposition (canonical orientation).  
• Optional CoordGen headers (not in RDKit tree).

-------------------------------------------------------------------------------

## 5. Rust-port notes

1. Provide `depictor` module offering `compute_2d_coords(mol: &mut Molecule, opts: &Options)`.
2. Use `nalgebra` for 2-D geometry and PCA alignment.  
3. Ring templates: store hash-map `smarts_hash → Vec<Template>` loaded from JSON at compile time with `include_str!`.
4. Sampling can utilise `rand` crate, while overlap scoring uses bounding boxes and line intersection tests.
