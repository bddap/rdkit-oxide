# GraphMol – DistGeomHelpers Sub-module Map

Location: `rdkit/Code/GraphMol/DistGeomHelpers`

This folder provides **high-level utilities for distance-geometry based 3D
coordinate generation ("embedding")**.  It sits on top of the lower-level
numerical engine found in `rdkit/Code/DistGeom/` and exposes a convenient
API used by `Chem.AllChem.EmbedMolecule()` and friends in Python.

--------------------------------------------------------------------------------

## 1. Public API surface

### `EmbedParameters` (in `Embedder.h`)
Monolithic parameter struct (≈50 fields) controlling every aspect of the
embedding pipeline:
* `maxIterations`, `timeout`, `numThreads`, `randomSeed`
* Flags: `enforceChirality`, `useExpTorsionAnglePrefs`, `useBasicKnowledge`,
  `useMacrocycleTorsions`, `forceTransAmides`, …
* Distance geometry knobs: `boxSizeMult`, `boundsMatForceScaling`
* Pruning knobs: `pruneRmsThresh`, `onlyHeavyAtomsForRMS`, `useSymmetryForPruning`
* Failure tracking: `trackFailures` + `std::vector<unsigned int> failures` that
  indexes the enum `EmbedFailureCauses`.

Helper ctors build *classic*, *ETKDG* and *ETDGv3* presets that mirror the
Python keyword shortcuts.

### Main functions (`Embedder.cpp`)

```
unsigned int EmbedMolecule(ROMol &mol, const EmbedParameters &params);

std::vector<int> EmbedMultipleConfs(ROMol &mol,
                                    unsigned int numConfs,
                                    const EmbedParameters &params);
```

The first embeds **one** conformer (returning its id) while the second embeds
`numConfs` conformers in parallel threads (returns vector of ids, −1 on
failure).

## 2. Internal helpers

| File | Role |
|------|------|
| `BoundsMatrixBuilder.{h,cpp}` | Derives 1-2/1-3/1-4 (and optional 1-5) upper & lower bounds from molecular topology, van-der-Waals radii and heuristic ring rules. Wrapping convenience around `DistGeom::BoundsMatrix`. |
| `EmbedderUtils.cpp` | Shared utilities: RMS pruning filters, centroid alignment, copy of ETKDG torsion-angle preference tables loaded from `Data/` folder. |

| `Wrap` | SWIG bindings exposing `EmbedParams` class and `EmbedMolecule()` wrappers to Python. |

## 3. Embedding workflow (simplified)

1. **Bounds matrix construction** – call `setTopolBounds()` to fill an
   `N×N` matrix with lower/upper bounds derived from bond lengths, angles and
   torsion heuristics. Triangle smoothing (`DistGeom::triangleSmoothBounds()`).

2. **Initial coordinate generation** – Classical DG: pick random distances via
   `DistGeom::pickRandomCoordinates()` (or eigenvalue seeded unless
   `useRandomCoords` is set).  Optionally repeated until *nTry = maxIterations*
   to satisfy lower bound violations.

3. **Force-field refinement** – If `useBasicKnowledge` or torsion prefs are on,
   an auxiliary force field (ETKDG) is constructed; otherwise a pure DG
   optimiser is run.  The optimiser works in 4D then projects to 3D for better
   convergence.

4. **Chirality and ring flip checks** – Post-minimization validation ensures
   tetrahedral and double-bond stereo match the input. Failures are counted in
   `EmbedFailureCauses`.

5. **RMS pruning** – If `pruneRmsThresh` ≥ 0, conformers closer than the
   threshold (RMSD of heavy atoms) are discarded on the fly. When
   `useSymmetryForPruning` is on, atom mapping generated by symmetry classes is
   used for faster RMSD.

6. **Timeout and progress callback** – Steps 2-4 periodically call the user
   supplied `callback` (if any) and abort if `timeout` is exceeded.

--------------------------------------------------------------------------------

## 4. Dependencies

• `DistGeom` core for bounds matrices and 4D distance geometry optimisers.  
• `ForceFieldHelpers/UFF` when knowledge-based post-processing is requested.  
• `RDGeom` for `Point3D` math.  
• `SimDivPickers` (indirect) for RMS pruning of large conformer ensembles.

--------------------------------------------------------------------------------

## 5. Rust-port notes

1. Bounds matrix → `nalgebra::DMatrix<(f64,f64)>` where each entry stores
   `(lower, upper)`.
2. Distance geometry embedding can leverage the `openmm-sys` crate _or_
   implement a light-weight 4D DG optimiser using L-BFGS from `argmin`.
3. Multi-threaded embedding maps to `rayon::par_iter()` over conformer indices.
4. Stereo validation will re-use code from the future `stereo` module (see
   GraphMol_Core notes).
